## 可复制提示词

请帮我把研栖 LabNest 完整部署为实验室正式使用的平台，供教师和学生共同访问。

项目仓库：[https://github.com/AdamRain/LabNest](https://github.com/AdamRain/LabNest)

请先阅读仓库的 README.md、docs/DEPLOYMENT.md 和相关配置模板，再根据目标机器的实际环境执行部署。

我的部署信息：

- 目标机器：［当前电脑，或远程服务器的连接方式］
- 操作系统：［不知道可以先检查］
- 访问范围：［仅本机／实验室内网／校园网／公网］
- 网站域名及证书：［已有信息；尚未准备可以留空］
- 首个管理员姓名及邮箱：［填写自己的信息］

如果信息不完整，请先检查能自动确定的内容，再询问确实缺少的信息。密码、SSH 私钥、邮箱授权码等敏感信息由我在本机安全填写，不要求我粘贴到聊天中。

请完成以下工作：

1. 检查操作系统、运行环境、目录权限、端口及已有服务。选择已发布的稳定版本，记录版本号。已有网站、数据库或配置须先备份，避免覆盖。
2. 按项目要求安装 Node.js 和依赖，运行测试。正式站使用独立空库，不运行 Demo 生成脚本，不导入演示资料，也不使用公开的 Demo 口令。
3. 设置独立的代码、数据、配置和备份目录，使用普通服务账号运行程序。让启动、管理员创建和备份命令始终读取同一份正式环境配置及数据库。
4. 创建首个管理员账号并生成独立随机密码。初始密码保存在仅本人可读的本机文件中，交付时告诉我文件位置，避免出现在公开日志、截图或仓库中。
5. 配置实际访问地址及 HTTPS。按部署文档选择直接 TLS 或同机反向代理，正确设置代理信任及 Cookie。若域名、证书或网络条件尚未满足，先完成不对外开放的准备工作，明确说明缺少什么，不自行降低安全要求。
6. 配置后台运行、异常重启和开机启动，并检查防火墙及访问范围。只调整本项目必需的设置，保留其他服务正常运行。
7. 配置数据库、邮件设置及必要配置文件的定期备份，写明恢复方法。邮件找回在我提供 SMTP 配置后启用；尚未配置时保留配置入口并注明待办。
8. 使用临时测试资料完成验收：实际地址访问、管理员登录、教师与学生注册审核、导师权限隔离、周报提交及修订、附件、动态回复、日历、个人主页和简历导出。确认待审核用户无法查看内部资料。测试资料与正式资料要明确区分。

完成后，请给我一份简明交付说明：

- 网站地址、部署版本和已验证的功能。
- 管理员初始密码文件的位置。
- 日常启动、停止、重启及查看日志的方法。
- 数据、配置与备份的位置，以及恢复方法。
- 后续更新流程、回退方法和仍需我处理的事项。

请持续完成能够执行的部署工作；遇到需要管理员授权、补充信息或外部网络配置时，说明具体原因和操作方法。不要把尚未验证的部分标记为完成。
